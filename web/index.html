Catch data leakage
before it ruins your model.

A model that scores 99% in testing and fails in production usually has a leak: the same rows or patients on both sides of the split, a feature that secretly contains the answer, or training on the future. Drop in your train and test files and find out in seconds.

What it checks

Duplicates

Test rows the model already saw in training. Rows are hashed so the check runs in linear time.

Near-duplicates

Copies with small changes, found with MinHash + LSH and only flagged when well above what chance explains.

Group leakage

The same patient, user or customer on both sides of the split, so the model learns the person, not the pattern.

Target leakage

Features that are the answer in disguise, like the price in another currency.

ID columns

Unique row identifiers a model can memorise instead of learning.

Temporal leakage

Time data split at random, so the model trains on the future.

Use it in your pipeline

The same code runs from the command line and exits with code 1 when it finds leakage, so it can block a CI build.

pip install leakcheck-ml
leakcheck train.csv test.csv --target label
